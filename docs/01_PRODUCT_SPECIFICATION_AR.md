# RAHHAL AI — وثيقة متطلبات المشروع الرسمية
**الإصدار:** 2.0 | **التاريخ:** 3 نوفمبر 2026 | **الحالة:** متطلبات معتمدة، التنفيذ لم يبدأ

## 1. هوية المشروع والحدود
- الاسم المبدئي: **RAHHAL AI / رحّال AI**. شركة سياحة **افتراضية** لأغراض التكليف الجامعي.
- المنتج: **Standalone Agentic AI Travel Assistant** يرد كتابةً وصوتًا ويمتلك أدوات وذاكرة وأفعالًا حقيقية تحت موافقة المستخدم. وليس بوت أسئلة وأجوبة أو موقع تسويق سياحي.
- لا موقع سياحة ولا صفحات وجهات ولا فيديو Hero ولا Landing Page ولا Storyboard موقع. يمكن واجهة تجربة مستقلة بسيطة وأنيقة للمحادثة والصوت وسجلات التنفيذ.
- أربعة البرامج المذكورة (الغردقة، النوبة، شرم الشيخ، الفيوم) **أمثلة أولية**، وليست حدًا أعلى ولا كل معرفة المساعد. كل قائمة الشركة قابلة للتوسعة والتحرير.
- لا يجب أن يتظاهر المساعد بأنه إنسان؛ يتحدث بدفء وذكاء، ويُعرّف نفسه بشكل واضح كمساعد ذكي تابع لشركة السياحة.

## 2. الهدف الأكاديمي
إثبات بناء AI Agent يحدد نية العميل، يختار أدوات مناسبة بشكل ديناميكي، ينفذ عمليات متعددة الخطوات، يستند إلى بيانات قابلة للتحقق، يحفظ سياقًا طويلًا وذاكرة مناسبة، يعالج فشل الأدوات، ويعرض Trace لخطوات التنفيذ *من دون إظهار استدلال داخلي مخفي*. ينبغي إعداد تحليل نظام وسلوك ونتائج اختبارات عملية.

## 3. سيناريوهات الوظائف الأساسية
### أ — برامج الشركة
- معرفة جميع الرحلات الموجودة في قاعدة البيانات والأسعار والمدد والخدمات ونقطة الانطلاق وسياسة الإلغاء ومواعيد السفر **إذا وُجدت بيانات فعلية**.
- بحث بالوجهة والمدة والميزانية ونوع الرحلة وعدد المسافرين، ومقارنة وتوصيات مبنية على الأرقام الفعلية في البيانات.
- إذا طلب عميل ترتيب الباقات من الأرخص، ينفّذ البحث ثم الفرز ويقدم نتيجة واضحة.
- كشف الصفات الناقصة: السعر للفرد أم للمجموعة؟ هل المواصلات مشمولة؟ ما تواريخ الانطلاق؟ لا يخترع إجابة.

### ب — السفر العالمي خارج برامج الشركة
- «هل فيه سفر برا؟»، «عندك برامج تركيا؟»، «دورلي على عروض اليابان أو إيطاليا» تعامل كـ **نية بحث عن عروض**، وليس مجرد سؤال عام.
- أولًا الاستعلام عن باقات الشركة؛ ثم، إذا لم تكفِ، **البحث في مصادر خارجية موثوقة ومرخصة** عندما تكون موصولة؛ البحث العام عن عروض شركات أخرى مع الروابط والمصدر وتاريخ التحقق.
- ميّز بوضوح بين (1) باقة تابعة للشركة (2) عرض جهة خارجية تم العثور عليه (3) خط سير/تكلفة تقديرية مولَّدة (4) معلومات عامة.
- لا يُعلن «متاح الآن» أو «السعر النهائي» إلا بتأكيد التوافر/السعر في المصدر الذي يسمح بذلك. سعر الويب وحده ليس ضمان حجز.
- إن لم توجد عروض يمكن توثيقها، يذكر ذلك ويقترح بحثًا بديلًا أو خط سير تقديري أو تحويلًا لموظف.
- لا حجز أو دفع أو إصدار تذكرة بدون تكامل تجاري حقيقي وموافقة واضحة.

### ج — المحادثة الطبيعية عبر جميع المجالات
- يجيب في العلوم والبرمجة والتعليم والرياضة والأسئلة العامة عند الطلب.
- **لا يقطع المحادثة خارج السياحة.** يكمل إلى أن ينتهي المستخدم أو تظهر نهاية طبيعية فعلًا؛ لا يُدخل ترويج السياحة في كل رد.
- بعد انتهاء المحادثة خارج السياحة *قد* يوجّه للسياحة في عبارة قصيرة ودودة، **اختياريًا**، مع مهلة تمنع تكرار التوجيه. رفض المستخدم يُحترم.
- يستوعب العامية المصرية، المزاح، التعبير الغامض، الاختصارات وFranco Arabic قدر المتاح؛ يسأل سؤال توضيح مناسب إذا لزم بدل رد «لم أفهم» آلي.
- النقد/الشتيمة الخفيفة: رد هادئ طبيعي مثل «ليه بس 😅 قولي إيه اللي ضايقك في ردي ونصلحه» مع حدود مهذبة لو الإساءة مستمرة؛ لا إهانة مضادة.
- يعترف بعدم اليقين أو نقص الأدلة بدل الهلوسة؛ يعالج أخطاء التوصيل برسالة لطيفة صادقة.

### د — الصوت
- ملفات Voice Notes مرفوعة من واجهة التجربة -> STT -> Agent -> إجابة نصية؛ دعم TTS اختياري حسب القدرة.
- Live Voice جلسة تفاعلية صوتية بزمن تأخير منخفض ومقاطعة وتبديل اللغة كتطوير لاحق، لا يعلن تشغيلها إلا بعد الاختبار.
- تفريغ صوت مع إشارة لانخفاض الثقة في الأسماء/الأرقام، والتأكيد قبل تسجيل بيانات.

### هـ — إدارة العملاء والعمل
- جمع الاسم ورقم الهاتف ومدينة المغادرة والوجهة والأيام والميزانية وعدد المسافرين **تدريجيًا وبموافقة صريحة**.
- إنشاء Lead أو Quote Request في CRM صغير أو قاعدة بيانات، وإرجاع رقم مرجعي حقيقي، وإتاحة تعديل البيانات.
- Handoff لموظف بشري عبر طلب منظم مع ملخص وأسئلة ناقصة، بدون ادعاء اتصال فعلي بقنوات غير متصلة.

## 4. تجربة الاستخدام
واجهة محادثة مستقلة فقط: عنوان المنتج، شارة «مساعد ذكاء اصطناعي تجريبي»، اختيار لغة، كتابة وإرسال، رفع/تسجيل صوت، حالة تشغيل ونتائج الأدوات، بطاقة مصدر عرض خارجي، وزر حذف/إدارة الذاكرة. واجهة Responsive وRTL مع إمكانية الوصول، لكن **لا صفحات تسويق/وجهات/موقع سياحة**.

## 5. المعايير غير الوظيفية
- Architecture modular + typed, unit/integration/e2e; no secrets in client or logs.
- Latency observable، tokens/costs per run، timeout/retry/circuit breaker/rate limit، idempotency للأفعال.
- أمان بيانات الأشخاص: موافقة وتشفير وصلاحيات ومدة احتفاظ وحق تعديل/حذف وعزل المستخدمين.
- مهام التسليم تشمل README وتشغيل محلي ومخططات تسلسلية وتقرير تقييم ومحتوى Demo واضح.

## 6. تعريف الإنجاز
لا يعتبر مجرد اتصال API بموديل لغة إنجازًا. الإنجاز = سؤال فعلي -> Tool call صحيح -> نتيجة متحققة -> إجابة -> Memory -> أثر مُسجل في DB عند الإجراء -> اختبار قابل للإعادة. تحقق من 30+ سيناريو على الأقل، بينها عدة محادثات متعددة الأدوار وحالات فشل.
